# CogniCare NER - Agentic Development Directives

**Core Architectural Rules**
* **UI Design Adherence:** Strictly follow the provided UI design screenshots for the core frontend development. However, for the cognitive games, you are free to optimize and improve the UI layouts if it results in a better user experience, provided you strictly maintain the established design language. You may also adapt the design for entirely new features not covered in the mockups.
* **Single App Structure:** Build one unified codebase with a role-based Mode Switcher for Elder Mode and Caregiver Mode[cite: 1]. Do not create separate applications[cite: 1].
* **Offline-First Mandate:** The application must run in a demo with no internet[cite: 1]. Read and write all core data to a local database (SQLite, WatermelonDB, or Realm) first, treating the backend purely as a sync target[cite: 1].
* **Agent Boundaries:** Ask the user before making any irreversible architectural choices that are not explicitly defined in the PRD[cite: 1].

**UI & Technical Constraints**
* **Accessibility Standards:** Enforce a baseline font size of 18–20sp, large tap targets of at least 48x48dp, and a high contrast color palette[cite: 1]. 
* **Safe UX:** Failure states must be gentle and encouraging[cite: 1]. Avoid punishing mechanics, aggressive game-over sounds, or complex double-tap gestures[cite: 1].
* **Speech Provider:** Use the **Sarvam AI API** (key already provisioned as `SARVAM_API_KEY`) for all TTS and STT — Bulbul for text-to-speech, Saarika/Saaras for speech-to-text. Sarvam is cloud-only with no on-device model, so it cannot be called live during gameplay without breaking the offline-first mandate.
* **Object Storage:** Use **Cloudflare R2** (S3-compatible; keys already provisioned) for all uploaded/generated media — family photos, caregiver-recorded reminder voice notes, and the pre-generated TTS audio bank described below.
* **Asset Loading:** Bundle all game assets locally or cache them after the first download; do not use on-demand asset fetching during gameplay[cite: 1]. For voice: pre-generate Sarvam TTS audio for every fixed instruction/reminder/encouragement string per supported language ahead of time, store the files in Cloudflare R2, and sync/cache them to the device so playback at runtime is always local — never a live Sarvam call. Live Sarvam STT for voice commands is the one exception that requires connectivity; when offline, disable voice commands gracefully and fall back to on-screen buttons rather than blocking the user.

**Development Workflow**
* **Strict Build Order:** You must build strictly according to the 7-stage order defined in the PRD to ensure the app is demo-able at every stage[cite: 1].
* **Verification:** After completing any stage, run a local build to verify there are no compilation errors before committing.
